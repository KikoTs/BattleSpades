# Pre-release soak — 2026-09-26

A long run of a production-like server to look for problems that only show up over time (memory, tick creep, transitions, bot worker, anticheat/conduct false positives). This is measurement only. No server code was changed.

## TL;DR

- **Stability: good.** In 94 minutes with 14 bots there were 45 transitions (33 map, 12 mode). All of them succeeded. All 28 maps and all 9 target modes were loaded and unloaded. There were 0 ERROR records, 0 tracebacks and 0 subsystem failures. The native fault log is empty. No access violations happened on this (flaky-RAM) machine.
- **Tick time: good and flat.** Median p50 was 0.65–0.69 ms. Median window p99 was 1.4–1.7 ms, with no creep (p99 trend −0.6 ms/h). The effective rate never dropped below 59.95 Hz. 31 of 338,930 ticks exceeded 10 ms.
- **Anticheat / conduct: no false positives.** There were 0 `anticheat` records and 0 counters on bots or humans, and 0 `conduct` records. The AFK timer does exactly what it says: warning at 540 s idle, kick at 600 s idle, verified with a real client.
- **Problems found (ranked below):**
  1. A rollover disconnects humans still on team select.
  2. The "off-thread" VXL preflight freezes the whole server for up to ~0.4 s.
  3. Grave explosions cause 5–37 ms tick spikes.
  4. 20thCenturyTown's 524 decorative flares make it the slowest map for bots.
  5. The RSS floor stepped up once, from ~90 to ~130–150 MB, and then plateaued. The cause is unexplained.

## Setup

- Harness: `scripts/soak/soak_server.py`. It runs the real `BattleSpadesServer` in-process, like `server/launcher.py`: gc.freeze, faulthandler, the bounded queue logger, ENet on UDP **27020**, plugins, anticheat and conduct.
- Only these overrides were applied:
  - 14 backfill bots with `worker="process"`, `clean_slate_games=3` as shipped.
  - `[modes.*].time_limit = 180 s`.
  - `map_rotation` set to all 28 `maps/*.vxl`.
  - Revival and Steam off, with separate log, ban and report paths.
- Rotation:
  - The natural end-of-round vote handled map changes (bots-only votes resolve deterministically through the whole catalog).
  - The harness switched mode through the production `/mode` path (`MatchTransitionService.request_mode_change`) after every 2 natural rollovers. Each switch happened 30 s into a round.
  - Modes cycled `tdm → ctf → oc → dia → tc → mh → dem → zom → vip`.
  - After 90 minutes, a sweep loaded the 10 maps the vote had not reached.
- Sampling:
  - Every 15 s, the harness recorded:
    - server and bot-worker RSS, Python allocated blocks, asyncio tasks, threads and handles;
    - tick p50/p95/p99/max for the window, drained from `RuntimeMetrics`;
    - effective tick Hz, event-loop lag (a 50 ms sleep probe) and subsystem p99/max;
    - every server deque length, and peer `reliableDataInTransit`/RTT;
    - worker status, spawn-selection timing (wrapped `choose_team_spawn`/`rescue_spawn`/`emergency_spawn`/`WorldManager.get_spawn_point`), and anticheat counters split bots/humans.
  - A logging handler counted every record and kept all WARNING+ records, every `anticheat`/`conduct` record, and the first tracebacks.
- Runs (all output under `logs/soak/`, which git ignores):

| run | purpose | length |
|---|---|---|
| `main-20260926` | full soak: 14 bots, 9 modes, 28 maps | 94.2 min (90 min plus the sweep) |
| `afk-20260926` | AFK timing with a real idle client (London TDM, 25 min round, 6 bots) | 16 min |
| `profile-20260926` | `--profile-entities --profile-stalls` on the maps/modes that spiked | 15 min |

- A real client (the tracer dev client, console **32899**, tracer 32900) joined the main soak for 12 minutes and the AFK run for 12.5 minutes, using `scripts/soak/soak_client.py` and `auto_join`.
- All processes were stopped afterwards. Ports 27020, 32899 and 32900 are free, and no orphaned worker processes remain.

## Problems found (ranked)

### 1. A rollover disconnects any human who is still on team select (medium-high)

- **What happened:**
  - 07:43:51: the natural vote moved the server to Atlantis. The client was re-sent InitialInfo and the map, then sat on team select (`MenuScene`, `player: False`, `connected: True`).
  - 07:44:23: a mode rollover fired (the driver's `/mode` path, 32 s after the map change).
  - The server immediately logged `ENET DISCONNECT from 127.0.0.1:57591`.
  - The client stayed disconnected (`connected: False` for the remaining 9 minutes).
- **Cause:** `server/match/__init__.py` `_rollover` treats every connection with `in_game == False` as "mid-handshake" and calls `connection.disconnect(reason=ERROR_MATCH_ENDED)`. A client that has finished loading but not yet picked a team or class counts as not in-game.
- **Impact:** this applies to *any* rollover, including the natural end-of-round map change. A human who is choosing a class when the round ends, or when an admin runs `/map` or `/mode`, gets dropped with "match ended" instead of being carried into the next map.
- **Evidence:** `logs/soak/main-20260926/server.log` lines 582–629, and `client_poll.jsonl` from t=85 s onward.

### 2. The "off-thread" VXL preflight freezes the whole server for up to ~0.4 s (medium)

- **What the soak saw:** the event-loop probe recorded stalls of 60–370 ms at **every** map or mode transition. Tick timing does not show them, because no tick runs during the stall; the fixed-step loop then catches up. The stall watchdog in `profile-20260926` caught the main thread parked in `GetQueuedCompletionStatus`, waiting to re-take the GIL while the preflight thread held it.
- **Offline reproduction:** a thread ran `MatchTransitionService._load_world_candidate` while the main thread measured 5 ms sleeps. Worst main-thread block per map:

  | map | worst main-thread block | load time |
  |---|---|---|
  | Classic | 399 ms | 1.0 s |
  | MayanJungle | 378 ms | 0.7 s |
  | 20thCenturyTown | 409 ms | 1.4 s |
  | Trenches | 139 ms | 4.1 s |

- **Cause:** cProfile shows `ServerVXL.__init__` (`server/runtime_vxl.py:200`) spends 0.42 s in the Cython `VXL.__init__` super call. That call never releases the GIL (there is no `nogil` in `aoslib/vxl.pyx`). The Python loops `_get_surface_z` (1.0 s over 73k calls), `_iter_explicit_voxels` and `_raw_vxl_size` add GIL-bound work on top.
- **Impact:** during `/map` and `/mode` this freezes live gameplay and ENet servicing mid-round, even though `request_map_change`'s docstring says the thread exists to avoid exactly that. For voted rollovers the freeze lands on the end-of-round scoreboard.

### 3. Grave explosions cause 5–37 ms tick spikes (medium-low)

- **Evidence:** `--profile-entities` recorded `GraveBehavior.on_tick` with a max of 21.0 ms and **73 calls over 5 ms in 15 minutes**. Every hook over 5 ms was a grave. The spikes were spread across Invasion/mh ×28, ArcticBase/mh ×19, Frontier/ctf ×13, AncientEgypt/tc ×10 and others.
- **Scale:** in the main soak, the `entities` subsystem hit 35.5 ms (Invasion/mh) and accounts for most of the 31 ticks over 10 ms.
- **Code path:** `GraveBehavior.on_tick` → `_detonate_deployable` → `server._apply_blast` (grave: block_damage 3, crater_radius 1, 7 s fuse on every death). The cost is likely in the crater and unsupported-collapse check, but this is not profiled deeper.
- **Other hooks for comparison:** `ProximityMineBehavior` max 4.0 ms, `PickupCrateBehavior` max 0.9 ms.

### 4. 20thCenturyTown is the slowest map for bots (low-medium)

- The map spawns **524 `map_flare` entities** (decorative lights). The next heaviest are ArcticBase with 42 and TheColosseum with 32.
- `BotDirector` snapshots every live registry entity and, above `_MAX_PERCEPTION_ENTITIES = 192`, sorts all of them by priority and by distance to every live player, on every perception frame.
- **Measured:** `bot_perception_entity_overflow` grew by **2,388 entities per second** on this map and by 0 on all others. The `bots` subsystem p99 was 3.9 ms here versus 0.6–0.9 ms elsewhere. This produced the worst segment p99 of the soak (4.15 ms).
- Decorative flares carry no gameplay meaning for bots. Filtering `map_flare` (type 13) out of perception removes the cost, and also stops flares pushing real entities out of the 192 cap.

### 5. One-off `bots_perception` spike at the start of Zombie (low)

- The first Zombie tick after the mode switch on SpookyMansion cost 53 ms (`bots_perception` 52.8 ms), followed by one 20.5 ms spike later in the same match.
- This is probably the first refuge election or snapshot build. It happens once per match, not continuously.

### 6. RSS floor stepped up ~40 MB once, then plateaued (low; needs a longer soak)

- See the Memory section. There is no unbounded growth in 94 minutes, Python objects are flat, VXL load/unload is ruled out, and the refuge atlas is ruled out.
- Recommendation: before calling memory clean for 24/7 hosts (the 512 MB fleet boxes), run a 6-hour soak with `thread_names` recorded, and run the zom/dem stretch on its own.

### 7. `WorkerStatus.restarts` also counts planned recycles (low, observability)

- All 15 "restarts" were planned `clean_slate_games` recycles. `/bots status` and any alert built on `restarts` cannot tell those apart from crashes.

### 8. Coverage gap, not a bug: bots never exercise the anticheat checks

- There are 0 counters of every kind on bots, including the log-only shot-origin, aim, backlog and starvation checks. Bots apparently bypass packet validation.
- "No bot false positives" is therefore trivially true, and says nothing about whether those checks misfire. Only real clients under packet loss can validate them (`scripts/udp_lag_proxy.py` plus a combat client).
- The idle-client test covered AFK only, not shooting.

A harness note: the only ERRORs ever seen (`end sequence failed` ×2) came from the first smoke run and were caused by a bug in the harness's own rollover wrapper (a `kind` keyword clash). That was fixed before the main soak and is not a server bug.

## Re-running

```
# full soak (about 95 min); stop early with Ctrl+C or by creating <out>/STOP
py -3.12 scripts/soak/soak_server.py --minutes 90 --sweep --out logs/soak/<run>
# optional real idle client while it runs (console 32899, tracer 32900)
py -3.12 scripts/soak/soak_client.py --server 127.0.0.1:27020 --hold-minutes 12 --rejoin --out logs/soak/<run>
# AFK timing: a long round so an idle human can reach 540/600 s
py -3.12 scripts/soak/soak_server.py --minutes 16 --round-seconds 1500 --modes tdm --bots 6 --start-map London --out logs/soak/<afk>
# profiling: per-entity-hook timing and main-thread stacks on event-loop stalls
py -3.12 scripts/soak/soak_server.py ... --profile-entities --profile-stalls
# report
py -3.12 scripts/soak/analyze_soak.py logs/soak/<run> --md logs/soak/<run>/report.md
```

Other options: `--bots`, `--worker process|thread`, `--round-seconds`, `--modes`, `--maps`, `--rounds-per-mode`, `--mode-change-delay`, `--sample-seconds`, `--port` (default 27020).
